# Architecture

The client presents a mail queue, source reader, actionable overview and reviewed draft editor using deep ink, jade and white surfaces, Inter body text and Krub headings. Three unread incoming examples start at the top with blue dots/bars; opening one records its version as read. Preview/header controls expand full mails and source inspection highlights exact text. The right panel has a single Next Step heading without divider bars. Populated sections sort before disabled empty sections, folder filters reflect reply need/reminders and a dismissed guide stays closed. Draft input signatures prevent reviewing an answer generated for old notes or another reply type. The server owns source versions and validates authoritative analysis results. Browser decisions never alter source messages.

| Boundary              | Implementation                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Source and recordings | `fixtures.ts`; NFC canonicalization, conservative duplicate removal, SHA-256 versions, exact quote spans; generated browser bundle   |
| Runtime contracts     | `contracts.ts` strict Zod structures and `domain.ts` relationship, owner, coverage, date and evidence validation                     |
| Provider              | `provider.ts`; bounded whole-message source envelope, strict structured analysis, actual streamed replies, abort signal              |
| Free model            | `openrouter-provider.ts`; official SDK, fixed NVIDIA model, zero price ceilings, exact-quote grounding and content streaming         |
| Added mail            | `custom-mail.ts`; validated incoming mail; local memory or session-scoped hosted Turso storage with expiry/reset                     |
| API                   | `api.ts`; signed sessions, origin controls, version checks, idempotency, SSE, static serving and readiness                           |
| Durable state         | `store.ts` / `turso-store.ts`; local SQLite or shared remote SQLite, transactional admission, cost ledger, TTL caches and sessions   |
| Browser transport     | `transport.ts`; protocol identity and sequence checks, terminal-event enforcement, deadlines and cancellation                        |
| Browser decisions     | `local-state.ts`; IndexedDB plus localStorage fallback; versioned synthetic actions and saved follow-ups; drafts/facts in tab memory |
| UI                    | `app.tsx`, `styles.css`; request-generation guards, modal focus management, keyboard actions and responsive layout                   |

Startup creates/reuses a signed session, loads bootstrap and the mail queue, then loads an example source and precomputed overview. Configured live mode governs explicit Fetch and reply generation; switching mails reads a valid cache or example without automatically spending a provider attempt. Adding an incoming mail triggers its first live Fetch. The example clock preserves 10 AM New York through DST; added mails use the actual New York calendar for reminders and overdue checks. Missing timezone/ambiguous dates receive no automatic overdue claim. Selecting a mail aborts outstanding work and increments a context generation; late callbacks cannot update another context. Offline startup uses `offline.ts` and the generated bundle after the session request fails.

Live cache identity includes thread/version, mode, schema, prompt, normalizer and model. Live and recorded artifacts remain separate. Cache results are validated again before use. Analysis commands replay a validated cache hit without another provider call. A concurrent cache miss for the same source receives an explicit busy response; subscriber fan-out is not implemented. Appending the waiting scenario changes source version, invalidating versioned draft/action contexts; reminder version markers trigger review.

Run admission uses a SQLite write transaction. Unknown costs from interrupted calls retain their reservation. One process owns a native SQLite file; multiple replicas cannot share it. Vercel uses remote Turso write transactions with durable provider counters and active-run leases. Starting another function does not invalidate a running stream; leases expire after two minutes. Shared admission also prevents duplicate simultaneous provider analyses for the same source. Added mail and its cached overview survive a change of function instance, remain session-scoped, and expire/reset together.

Deliberate deviations from the specification: native SQLite replaces Drizzle; native IndexedDB replaces an idb wrapper; React effects and context guards replace a reducer/query-cache layer; plain CSS and accessible native controls replace Tailwind/Radix. The application has one view and does not add unused router/query libraries. Tests verify the behavior of these choices; this is not an exact implementation of every prescribed library.
