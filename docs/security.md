# Security and data

Bundled inbox examples are synthetic. New mail accepts user-written incoming messages scoped to the signed session, with a maximum 24-hour lifetime and a one-hour overview-cache lifetime. The local SQLite preview holds these in memory; the Vercel deployment uses Turso so a different function instance can serve the next request. Reset removes added mail and its cached overview. Expired content is inaccessible and deleted during cleanup; database/provider backups may have separate retention. A session can add ten mails, with a shared cap of 200. The application renders bodies as React text. Provider credentials stay in an ignored local environment file or hosting secret manager. Local secret files have restricted Windows access. Credentials are not browser variables, source literals, artifacts or error messages.

OpenRouter/NVIDIA receives source text and reply facts for live operations. The free model may log/train on submitted content; the new-mail dialog asks for example content and warns against private information. The legacy OpenAI adapter uses `store: false`, which is not a universal zero-retention guarantee. Neither provider boundary is presented as confidential mailbox infrastructure.

Mutating APIs require a signed, expiring anonymous session. HttpOnly SameSite=Strict cookies use Secure for HTTPS origins. A blank SESSION_SECRET uses a persisted random SQLite secret. Explicit origins and cross-site request checks protect browser mutations; direct clients without Origin still require a valid session. Development additionally permits localhost:5173. Sessions are anonymous demonstration boundaries, not user authentication.

Bodies are limited to 32 KiB. Requests, facts, versions, metrics and intents use strict schemas. Unknown API paths return JSON errors; missing assets return 404. Standard security and request-ID headers are retained on SSE responses. Errors do not expose provider bodies or stacks to the browser.

Admission limits: two active runs per session, four active provider calls, twelve hourly/twenty-four daily provider attempts per session, and 40 daily OpenRouter attempts per deployment (250 for legacy OpenAI). Cached/recorded runs do not consume provider attempts or active provider slots. Limit responses distinguish browser and shared allowances and include a Retry-After time. Free requests reserve zero dollars but still consume an attempt, including failures. Every OpenRouter call pins the free model and sets zero price ceilings; there is no paid fallback. OpenRouter has an additional account-wide free-tier limit, which also includes requests from other tools or local previews. Legacy reservations enforce a $5 UTC-day ceiling, use conservative token caps, and retain unknown charges. Reservations are transactional and survive restart. Ordinary APIs are limited to 30 requests/minute/session per process; creation is capped at 60 sessions/hour in shared storage. Anonymous cookies are not a complete public abuse defense.

Idempotency binds a key to session and HMAC request identity. Active duplicate calls, changed bodies and completed replays return explicit conflicts instead of making another provider call. Cache entries expire after seven days and are revalidated. Sessions expire after 24 hours; stale run/cost history is retained for seven days and metrics for one day with per-session/global row caps.

The database stores session/run metadata, HMAC identities, costs, cached synthetic analyses, metrics and append scenario state. Hosted storage additionally holds session-scoped added mail and its cached overview until reset/expiry. It does not store supplied reply facts or draft bodies. Browser drafts and facts stay in tab memory and are cleared on reload. Older persisted draft entries are removed on startup. Synthetic decisions and reminders use IndexedDB with a localStorage fallback. Storage failure is surfaced. Undo holds the latest twenty local decision snapshots within the current UI session.

The guide's closed flag survives reset/reload. Browser decision/reminder storage contains identifiers and dates, not added-mail text. Native SQLite hosting requires one replica and a protected persistent volume; Vercel uses shared Turso storage and HTTPS. New function instances recover only expired run leases and preserve requests still running elsewhere. This remains a portfolio demonstration with example content rather than confidential mailbox infrastructure.
