# Evaluation

`pnpm test` runs domain, API/persistence/provider/protocol regressions, React workflow tests and offline-bundle tests. `pnpm fixtures:validate` checks the ten base scenarios and appended reply against exact quote slices, ownership, coverage and relationships. `pnpm smoke:built` launches the compiled application on an isolated port with an in-memory database, checks built assets/readiness/all ten briefs, and exercises recorded SSE analysis/reply.

The regression suite checks request validation, sign-in cookies and origin headers, scoped idempotency, admission limits, durable restart accounting, cache expiry, isolated metrics, source truncation, unsafe drafts, recipient selection, dates across timezone/DST boundaries, stale callback rejection, editing/review/copy, cancellation, reminders/undo, focus trapping, and offline append behavior. An actual OpenAI SDK HTTP mock verifies provider cancellation; it is not a paid model test.

Automated axe checks cover semantic accessibility in jsdom for the initial view, command palette and new-mail dialog. Color contrast is disabled there because jsdom cannot supply a real rendered page. The current redesign has not received a fresh rendered-browser inspection: automated browser access was rejected by the environment's browser policy. Historical screenshots show the earlier interface and are not current visual proof. Neither automated semantic checks nor a visual review would establish WCAG certification or a native screen-reader assessment.

The current suite additionally checks unread count/order/read persistence, full-mail expansion/collapse and highlighted-source collapse, visible Fetch failure/retry, permanent guide dismissal, section ordering, folder/search empty states, custom mail → live Fetch, fabricated quotes/owners, reasoning exclusion, free-model/zero-price routing, actual SDK cancellation, session privacy, memory-only caches, quotas, calendar reminders and source-direction consistency. Manual live scripts use the configured free model, validate evidence/facts and log example-only output or sanitized results. See the [latest unread and latency update](../deliverables/Email-Center-Read-State-and-Latency-Update.md) for outcomes and limitations.

`pnpm benchmark:built` writes repeatable local HTTP measurements, corpus results and source SHA-256 hashes. All eleven corpus variants must validate. The validator does not establish semantic model accuracy, user task success, or real productivity gains. Employer evidence should distinguish these dimensions.

Future live evaluation should annotate unsupported claims, wrong owners/dates, coverage omissions, incomplete/failed responses, review friction, latency and cost over repeated runs. Record the exact model, prompt, schema, source hash, source window and environment; never report a single plausible answer as a reliability score.
