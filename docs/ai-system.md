# AI boundary

Recorded mode uses reviewed synthetic extractions and conservative replies. It never generates availability or a new promise. Answering with custom facts requires live mode; unsupported recorded requests fail explicitly rather than impersonating a reviewed recording.

The primary xAI adapter uses AI SDK 7 with direct Grok 4.3, prompt `threadline-xai.v1`, a 4,000-token analysis cap and a 2,000-token reply cap. Reasoning is disabled, response storage is false, and standard processing is explicit. It uses the same current-note/source prompts and exact-quote validation as the optional OpenRouter path. Provider/model/prompt identity separates their caches. There are no tools, automatic retries or model fallbacks. Shared Turso reservations enforce $0.25/day and $4 total across local and hosted calls; successful token usage includes cached-input pricing. Pruning does not erase aggregate spend. The model ID and verified standard rates are pinned. See [xAI model/pricing](https://docs.x.ai/developers/models/grok-4.3).

The optional OpenRouter adapter uses the official SDK and `nvidia/nemotron-3.5-lightning:free`, prompt `threadline-openrouter.v5`, a 4,000-token analysis cap and reasoning effort `none`. The original `nvidia/nemotron-3-ultra-550b-a55b:free` is still accepted if explicitly configured on the server; it is not an automatic fallback. Other model IDs are rejected. Each request enforces zero prompt/completion/request prices, with latency sorting and no application retry. See [OpenRouter routing](https://openrouter.ai/docs/guides/routing/provider-selection) and the [Lightning free endpoint](https://openrouter.ai/nvidia/nemotron-3.5-lightning:free). The app starts without a model-catalog network dependency; a provider outage fails the affected operation rather than hiding the inbox.

Reply need means whether the viewer should respond next. A grounded current viewer request in the latest authored incoming mail establishes a needed response. A grounded request or pending follow-up addressed to a recipient of the viewer's outgoing mail establishes that the recipient owes the response. The same incoming viewer request cannot also establish a reminder for its sender without a separate participant obligation. Quoted requests do not trigger these rules. These direction checks correct mistakes observed in live tests; they do not prove arbitrary semantic correctness.

Source messages are serialized as JSON with subject, participant IDs/names and viewer identity. Redundant source hashes, repeated thread IDs, order fields and contact email metadata are omitted from the model prompt. Body content is still transmitted and can itself contain personal data. The full request is capped at 96 KiB. The most recent contiguous whole messages fitting a 12,000-character message budget are included; oversized newest messages are rejected. The model supplies exact quotes and participant IDs; the server computes offsets, owners, coverage and provenance. Only validated output replaces an overview. The legacy OpenAI adapter remains available with verified positive prices, `store: false`, strict structured output and a 2,200-token analysis cap.

Analysis commands replay valid cache hits without charging a provider attempt. A duplicate in-flight analysis is rejected before reservation; callers keep the existing brief and can retry. The server owns provenance. It checks structure, source version, exact evidence slices, included-message references, owners, claim IDs, deadline relationships, completion/answer evidence, decision supersession references, and calendar dates. Invalid results are discarded; the existing recorded brief remains available. These checks establish relationships and literal grounding, not complete semantic truth or hallucination immunity.

OpenRouter replies stream actual content deltas with a 2,000-token cap; the legacy OpenAI cap is 500. Browser disconnect, explicit cancellation and a 90-second OpenRouter / 45-second OpenAI server deadline abort the SDK request through its request-options signal. A stop/completed provider terminal is required; truncated replies remain incomplete and cannot be reviewed until edited. The client imposes a 15-second idle deadline and 120-second total deadline. Ten-second server heartbeats keep a quiet reasoning phase alive. A provider timeout has a distinct failure message, preserving the previous overview.

Each reply receives instructions for its selected intent only. Current notes take precedence over old viewer availability; earlier viewer-authored messages are excluded from reply context unless they are the latest message. Notes are rewritten naturally while preserving constraints and uncertainty. Offered times do not authorize a selection. Draft lint checks unsafe text, certain unsupported availability/promises, specific unconfirmed time choices, day/morning conflicts and invented blanket flexibility. Supported explicit clock/day availability can be paraphrased. These narrow checks are not a general semantic safety proof.

Drafts record their input signature in tab memory. Changing notes/type requires Update draft or a manual adaptation before review/copy; typing alone does not call the provider. Facts are bounded, version-scoped and private to tab memory. Review/copy reruns lint; edits invalidate review. Cancelled partial drafts require manual completion before review.

Automated tests use mocked output and both actual installed SDKs against local HTTP services to verify cancellation. Real free-model grounding and the added-mail workflow have separate manual checks, documented in the latest update. Successful examples are not a model-quality benchmark. Broad semantic evaluation and deployed SSE verification are still required before treating this as a production mailbox.
